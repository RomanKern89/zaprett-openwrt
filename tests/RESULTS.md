# Результаты финального тестирования zaprett для OpenWrt

Дата: 2026-09-17.

## 0. Как тестировалось

Стенд — изолированные виртуальные машины x86_64 на гипервизоре:

| Роль | Что это |
|---|---|
| тестовый роутер A | OpenWrt **25.12.5**, пакеты `apk` |
| тестовый роутер B | OpenWrt **24.10.8**, пакеты `opkg` |
| клиент | отдельная машина в LAN за тестовым роутером A — это и есть путь реального пользователя |
| сборочная машина | Ubuntu + docker, сборка пакетов в OpenWrt SDK |

Доступ к **реальному провайдеру** (а значит и к настоящему DPI) тестовые роутеры получали через временное
точечное исключение на домашнем роутере: правило действовало только для адресов тестовых машин, только в
памяти (не в конфигурации) и было снято сразу после проверок. Контроль, что остальная сеть не затронута:
эталонный домашний клиент всё время выходил в интернет через прежний туннель — проверено сравнением
внешнего адреса.

Правило отчёта: каждая строка — что проверено, какой факт это подтверждает и чем. Отрицательные контроли
указаны явно. Не проверенное перечислено в конце, без округления в свою пользу.

## 4. Веб-интерфейс (браузер)

Открыты все 6 страниц: Обзор, Стратегии, Списки, Репозиторий, Настройки, Диагностика. **Ошибок в консоли — 0.**
Язык русский. На обзоре видно состояние, движок, стратегию, включённые списки, применённость правил,
WAN-интерфейс, состояние ускорения; предупреждения объяснены человеческим языком с советом, что делать.
В мастере быстрой настройки показан объём памяти роутера (482 МиБ на стенде) и рекомендация по уровню;
сервисы, которым обход не поможет (WhatsApp, Instagram/Facebook, X, ChatGPT/Claude, Spotify), отмечены и
выключены с честной причиной.

## 5. Реальный трафик через провайдера

Базовый прогон **без обхода**: доступна **1 цель из 25**. YouTube, Discord, Telegram, RuTracker не
открывались вовсе (0 байт), российский сайт и сайт за Cloudflare — открывались. То есть DPI провайдера
подтверждён фактом, а не предположением.

Автоподбор (быстрый, 12 стратегий): лучшая — **`strategy-alt`, 15 из 25**; стратегия по умолчанию
`strategy-general` — 0 из 25 (у этого провайдера не работает).

С применённой `strategy-alt`, **с клиента за роутером** (это и есть путь пользователя), два повтора подряд:

| Цель | Результат |
|---|---|
| `https://www.youtube.com/` | 200, ~894 КБ |
| `https://i.ytimg.com/vi/…/hqdefault.jpg` | 200, 21 КБ |
| `https://discord.com/` | 200, 170 КБ |
| `https://rutracker.org/forum/index.php` | 200, 96 КБ (после включения сервиса мастером) |
| `https://telegram.org/`, `https://t.me/durov` | не открываются этой стратегией |

Важное наблюдение: с самого роутера Discord этой стратегией не открывался, а **с клиента — открывался**.
Путь трафика роутера (локальный выход) и клиента (проходящий трафик) обрабатывается по-разному, поэтому
автоподбор, проверяющий цели с роутера, даёт **заниженную** оценку. Это ограничение метода, а не дефект:
пользователю важен клиентский путь.

Мастер быстрой настройки проверен вживую: включение сервисов YouTube, Discord, Telegram, RuTracker добавило
нужные списки и список IP-сетей Telegram, режим «белый список», обязательные исключения.

## 8. Удаление и чистота системы

Проверка на 24.10.8 (opkg) **двумя полными циклами** «свежая установка → `install.sh --uninstall --purge`»:

```
цикл 1: установлено пакетов=4, после purge каталогов=0 файлов=0
цикл 2: установлено пакетов=4, после purge каталогов=0 файлов=0
```

Проверялись пути `/usr/share/zaprett`, `/usr/share/ucode/zaprett`, `/usr/libexec/zaprett`, `/etc/zaprett`,
`/etc/config/zaprett`. После проверки пакеты поставлены снова и служба запущена: `running=true`,
`nft_applied=true`.

**Оговорка о методе:** промежуточный прогон, в котором остатки нашлись, шёл на системе с пакетами
ПРЕДЫДУЩЕЙ сборки (без `postrm`) — то есть это были следы старой установки, а не дефект новой. Правильная
проверка исправления скриптов удаления — только со свежеустановленного пакета.

## 10. Что НЕ проверено

- Работа на реальном железе (MIPS/ARM-роутеры) — только x86-виртуальные машины; тайминги на слабом CPU
  не измерены.
- **Полный перебор всех 64 стратегий** запускался, но его файл результатов лежал в tmpfs (`/var/run/zaprett`)
  и был стёрт последующей переустановкой пакетов, а временное исключение для доступа к реальному провайдеру
  к этому моменту уже снято — поэтому таблица «стратегия → сколько целей открылось» **не сохранена и не
  воспроизводима**. Достоверными считаем только результаты быстрого перебора (12 стратегий) из §5.
- Telegram: помогает ли какая-либо стратегия против текущих ограничений — не найдено.
- Подписки на внешние списки (Re:filter, antifilter, Cloudflare) вживую не загружались на стенде: проверены
  только разбор, нормализация и учёт памяти (автоматические тесты).
- Обновление пакетов поверх установленных (r1 → r2) на роутере; проверено только в контейнерах при сборке.
- Совместная работа с VPN/прокси и маршрутизацией по политике на том же роутере — не проверялась намеренно.
- Веб-интерфейс проверялся в браузере на движке Chromium; Firefox и Safari не проверялись.

## 15. Что НЕ проверено в 1.1.0

- Реальный DPI провайдера для новых функций и стратегий `z2-`: стенд не имел прямого выхода к провайдеру.
- Прирост скорости от своей таблицы ускорения на слабых роутерах: на x86-виртуальных машинах разница в пределах
  разброса; измерения на MIPS/ARM не было.
- Реальное железо MIPS/ARM (как и в 1.0); бинарники движка для всех архитектур запускались только в эмуляторе qemu.
- Запуск workflow в GitHub Actions и онлайн-фид на GitHub Pages: скрипты прогнаны на сборочной машине, в GitHub не публиковались.
- Голос Discord и QUIC вживую; IPv6 (на стенде нет IPv6).
- Вложения Discord (`discord-attachments-uploads-prd.storage.googleapis.com`) не вошли в собственные списки: адрес не
  подтверждён ни сессией без входа, ни кодом клиента; при проблемах добавьте его в «Мои домены».
