# luci-app-zaprett — веб-интерфейс zaprett для OpenWrt

> Версия документа: 1.1 (2026-09-17, сверка с готовым бэкендом). Пакет: `packages/luci-app-zaprett`
> (1.0.0-r1, noarch, MIT). Контракт — `docs/ARCHITECTURE.md` v1.2 (§4 UCI, §5 генератор и граница исключений,
> §6.2 CLI, §6.3 задачи, §9 пресеты, §10 автоподбор, §11 LuCI), поля ответов — `docs/BACKEND.md` §6.
> Поддерживаются OpenWrt 24.10 (LuCI 24.10, opkg) и 25.12 (apk).

## 1. Состав пакета

```

├── htdocs/luci-static/resources/

├── po/ru/zaprett.po                                  полный русский перевод → пакет luci-i18n-zaprett-ru
├── root/etc/uci-defaults/80_luci-zaprett             сброс кэша меню LuCI и reload rpcd (первая загрузка образа)
├── root/usr/share/luci/menu.d/luci-app-zaprett.json  «Службы → zaprett» и 6 подстраниц
├── root/usr/share/rpcd/acl.d/luci-app-zaprett.json   права только на методы luci.zaprett и uci zaprett
├── root/usr/share/rpcd/ucode/luci.zaprett            rpcd ucode-плагин, объект ubus luci.zaprett
```

Каталог `tests/` не устанавливается: `luci.mk` копирует только `htdocs`, `root`, `ucode`, `luasrc`, `src`.

Общие правила интерфейса:

- Весь текст — через `_()` (msgid на английском), перевод — `po/ru/zaprett.po` (571 строка, 100 %).
- Сообщения бэкенда (`message`, по контракту уже на русском) показываются как есть; для кодов уровня веб-интерфейса
  (`backend_missing`, `timeout`, `reply_too_large`, `tmp_unavailable`, …) и транспортных ошибок RPC (нет прав,
  модуль rpcd не загружен, таймаут, HTTP-ошибка) — собственные понятные тексты.
- Кнопки блокируются на время операции (`ui.createHandlerFn`), долгие операции — только фоновые задачи бэкенда
  с опросом через `poll.add`; опрос снимается по окончании задачи, при ошибках связи (5 подряд) и на `pagehide`.
- Отмена задачи: бэкенд отвечает сразу `{state:"cancelling"}` и довершает отмену при следующем опросе
  (`job status`, `test status`, `status`). Интерфейс показывает «Отмена запрошена…», продолжает опрос до
  `state != running` и так же обрабатывает `{state:"restored"}` (задачи нет, снят оставшийся режим автоподбора)
  и таймаут запроса.
- Граница исключений (контракт v1.2 §5): доменные исключения действуют только там, где сайт узнаётся по имени.
  Если тот же сайт попадает во включённый список IP-сетей или подписку, его соединения всё равно обрабатываются —
  интерфейс говорит это прямо и советует добавить адреса в «Исключения IP-сетей».

## 3. rpcd-плагин `luci.zaprett`

Файл `/usr/share/rpcd/ucode/luci.zaprett`, загружается rpcd при старте (любой обычный файл каталога, не
доступный на запись всем). Использует только стандартную библиотеку ucode и модуль `fs` — есть в 24.10 и 25.12
(проверено на стендах: `ucode -l fs` и `ucode -c`).

### 3.1. Как вызывается CLI

```
system([ '/bin/sh', '-c', 'in=$1; out=$2; err=$3; shift 3; exec "$@" <"$in" >"$out" 2>"$err"',
         'zaprett-luci', <stdin-файл|/dev/null>, <out-файл>, <err-файл>, '/usr/bin/zaprett', <аргументы…>, '--json' ],
       <лимит> * 1000)
```

- Аргументы передаются массивом (execve) — оболочка их не разбирает; скрипт `sh` постоянный и только
  перенаправляет потоки. `fs.popen()` не подходит: принимает лишь строку для `/bin/sh -c` (проверено: массив →
  `Invalid argument`).
- `exec` заменяет `sh` процессом CLI, поэтому лимит `system()` (SIGKILL) останавливает сам CLI. Вывод читается из
  файла, а не из канала: фоновые процессы бэкенда, унаследовавшие stdout, не задерживают ответ (первая версия на
  `popen` + сторож зависала на 40 с — поймано тестом).
- Временные файлы — в `/var/run/luci-zaprett` (0700, root). Каталог создаётся при первом вызове; если это ссылка,
  он не принадлежит root или доступен группе/другим — `tmp_unavailable`. Файлы удаляются после каждого вызова.
- Текст для `strategy save` / `user set` и JSON для `sources save` пишутся во временный файл и подаются на stdin.
- Лимиты: 15 с на чтение, 19 с на изменения (таймаут RPC в браузере — 20 с); вывод CLI читается до 4 МиБ; ответ
  ubus — не больше 900 000 байт (ограничение сообщения ubus 1 МиБ). Для `test_status` при превышении из
  результатов удаляются `targets` и ставится `targets_trimmed: true`.
- Разбор: ответ должен быть JSON-объектом; иначе `{ok:false, error:"backend_error", message:"… exited with code N
  and returned no valid JSON: <начало вывода или stderr>"}`. Если в объекте нет булева `ok`, он выводится из кода
  возврата; при `ok:false` без `error` подставляется `backend_error`, без `message` — stderr.

### 3.3. ACL

`luci-app-zaprett`: read — `status, items, strategy_show, user_get, check, repo_list, presets, sources_list,
test_status, job_status, job_log, diag` + `uci: zaprett`; write — остальные 18 методов + `uci: zaprett`. Никакого
`file.exec`, доступа к файлам или интерпретаторам. Страница «Настройки» дополнительно пользуется общими ACL LuCI
(`luci-rpc getHostHints`, сетевые интерфейсы) — у администратора они есть; без них подсказки устройств просто не
показываются.

## 4. Безопасность вывода и ограничения LuCI

- **`E()` и `dom.content()` небезопасны для строк.** В LuCI (и 24.10, и master) `dom.append(node, 'строка')`
  выполняет `node.innerHTML = строка`; текстовые узлы создаются только для элементов массива. Поэтому все данные
  с роутера передаются как `[строка]` (`zc.txt()`), заголовки `ui.showModal()`/`ui.addNotification()` — тоже
  массивом. Проверено чтением `luci.js` в обеих ветках и минифицированного `/www/luci-static/resources/luci.js`
  на обоих стендах.
- Логические атрибуты через `E()` задаются `setAttribute`, поэтому `'disabled': false` всё равно отключает
  кнопку — в коде используется `'' | null`.
- **Тело POST к `admin/ubus` не больше 100 КиБ** (`HTTP_MAX_CONTENT = 1024*100` в `/usr/share/ucode/luci/http.uc`
  на 24.10.8 и 25.12.5). Редактор своих списков проверяет размер JSON-строки (≤ 99 КиБ), редактор стратегий — лимит
  бэкенда 64 КиБ. Больший список — копировать на роутер по SSH.
- Ответ ubus ограничен 1 МиБ (`UBUS_MAX_MSGLEN`), см. §3.1.
- rpcd обрабатывает ucode-методы синхронно: пока идёт вызов, остальные запросы LuCI ждут. Все долгие операции —
  задачи бэкенда, отмена отвечает сразу (§2).

## 5. Совместимость 24.10 / 25.12

Используемые API сверены с ветками `openwrt-24.10` и `master` репозитория LuCI и с установленными файлами на
стендах (OpenWrt 24.10.8 и 25.12.5): `rpc.declare({…, reject:true})`, `ui.showModal/hideModal`,
`ui.addNotification`, `ui.addTimeLimitedNotification`, `ui.createHandlerFn`, `ui.tabs.initTabGroup`, `poll.add/remove`,
`dom.content`, `form.Map/NamedSection/ListValue/MultiValue/DynamicList/Flag/Value` (`retain`, `optional`,
`datatype`), `tools.widgets.NetworkSelect`, `network.getHostHints()` (`getMACHints`, `getIPAddrByMACAddr`),
`uci.load/get/add/unload`, `String.prototype.format` (`%m`). Ничего из появившегося только в 25.12
(`fs.exec_direct` с прогрессом и т. п.) не используется. JS в стиле LuCI 24.10 (стрелочные функции, `?.`, `??`) —
собственный код LuCI 24.10 написан так же, а `jsmin` из 24.10 понимает шаблонные строки.

## 6. Перевод

- msgid — английский, одной строкой, без двойных пробелов (LuCI нормализует пробелы при поиске перевода).
- `po/templates/zaprett.pot` генерирует `tests/check_static.py --write-pot` по тем же правилам, что
  `build/i18n-scan.pl` LuCI: `_('…')` из JS и `title`/`description` из `menu.d`/`acl.d`.
- Русский перевод — `po/ru/zaprett.po` без множественных форм (`N_()` не используется), названия пунктов меню LuCI
  взяты из официального перевода LuCI («Применить», «Межсетевой экран», «Статус → Системный журнал»,
  «Система → Пакеты»).

## 8. Что сознательно не перенесено

| Функция приложения | Почему нет на роутере |
|---|---|
| Режим ByeDPI (ciadpi через VpnService, без root), его IP/порт/DNS, IPv6 для ByeDPI | Это обход через локальный VPN Android. На роутере трафик и так проходит через nfqws; стратегии ByeDPI в каталоге показаны как «не поддерживается на роутере». |
| Плитка быстрых настроек (QS), уведомление «zaprett работает» | Элементы Android. Состояние видно на «Обзоре». |
| Проверка обновлений приложения (`update.json`), диалог обновления | Пакеты обновляются пакетным менеджером из фида (`opkg`/`apk`). |
| «Периодически перезапускать сервис» | procd сам перезапускает движок при падении (`respawn`). |
| Аналитика Firebase | Не нужна и не допустима на роутере. |
| Запросы root / Magisk-модуль / разрешения хранилища и уведомлений | На роутере служба работает от root через procd, разрешения Android не существуют. |
| «Обновлять статус при запуске Главной», «Показывать полный путь», «Показывать системные приложения» | Статус обновляется автоматически раз в 5 с; путей и приложений в интерфейсе нет. |
| Импорт произвольного файла с устройства | LuCI принимает не больше 100 КиБ за запрос; вместо загрузки — редактор своих списков и подписки по ссылке (большие файлы роутер скачивает сам). |
| «Сброс настроек» (раздел «Отладка») | Опасно одним нажатием; настройки меняются формой «Настройки», конфиг `/etc/config/zaprett` восстанавливается переустановкой пакета. |
| URL репозитория обновлений приложения | См. «Проверка обновлений». |

## 9. Сверка с бэкендом (2026-09-17, контракт v1.2)

Проверено по исходникам `packages/zaprett` (`commands.uc`, `service.uc`, `sources.uc`, `tester.uc`, `job.uc`,
`repo.uc`, `strategy.uc`) и `docs/BACKEND.md` §6. Настоящий CLI не запускался (тестирование — финальный этап).

Сошлось: все поля, которые читает интерфейс (`status`, `items`, `check`, `strategy show/set/save`, `user get/set`,
`repo list`, `sources list`, `presets`, `wizard apply`, `test status/apply`, `job status/log/cancel`, `diag`),
закрытый список 19 предупреждений, единое поле `reloaded`, коды ошибок и дополнительные поля
(`errors[]`, `dry_run`, `used_by`, `skipped`, `job_error`, `failed[]`).

Приведено в соответствие при сверке:

1. Отмена задач — два шага (`cancelling` → завершение при опросе) и ответ `restored` у `test stop`.
2. Подписки — поля `min_entries`, `status` (`ok|error|never|invalid`), `message`, `downloaded` из `sources list`;
   `min_entries` больше не читается из UCI. `source_save` отправляет только изменённые поля (бэкенд сохраняет
   остальные), поэтому переключатель «Загружать» не перезаписывает адрес и период.
3. Подписку можно включить в работу до первой загрузки (бэкенд это допускает): переключатель «Использовать»
   активен всегда, а состояние объясняет предупреждение `source_not_downloaded`.
4. Мастер: показываются `skipped` (сервисы с `works=no`), включённые и выключенные подписки, `job_error` и
   ход задачи `sources-update`.
5. `profile_unfiltered` — подробности из `details.generate.details.unfiltered_profiles` (в `status`) и
   `details.unfiltered_profiles` (в `check`): номера частей стратегии и их порты.
6. Обрезка результатов автоподбора: бэкенд оставляет подробности у первых 10 результатов (≤ 100 целей),
   интерфейс показывает пометку и по полю `results.targets_trimmed`, и по своему `targets_trimmed` плагина.
7. `items --type byedpi` больше не отклоняется плагином (тип есть в бэкенде).
8. Граница исключений (§5 v1.2) объяснена честно в «Списках» и «Настройках», см. §2.

Осталось на финальный этап (не правится сейчас):

- `diag` у бэкенда собирает список пакетов с таймаутом до 60 с, а лимит вызова из веб-интерфейса — 19 с
  (таймаут RPC в браузере 20 с). На медленном роутере отчёт может не успеть; интерфейс покажет «роутер не успел»,
  отчёт остаётся доступным по SSH. Нужна либо более быстрая сборка отчёта, либо отдельная кнопка «полный отчёт».
- Обрезка `test_status` в плагине оставлена как страховка: при 64 стратегиях и подробностях у 10 из них ответ
  укладывается в сообщение ubus, но при изменении лимитов бэкенда страховка не даст превысить 1 МиБ.
